- [ ] 2. Domain: 純粋ロジック

  - 再試行可能な失敗を 6 種、再試行不可を 2 種として定義する
  - モデル不存在をステータス 404 として扱い、応答本文のテキスト一致による判定を行わない
  - 失敗の事実を保持する値オブジェクトと、明示的エラー送出用の例外型を提供する
  - 完了状態: 対応表の全区分（再試行可能 6 ステータス・3xx・その他 4xx・その他 5xx・範囲外の値）を網羅した単体テストが通り、再試行可否集合が分類定義と一致することを検証できる

- [ ] 2.2 (P) 接続先 URL の検証と endpoint 構成を実装する

  - ホストは角括弧付き IPv6 literal、IPv4 ドット 4 組、ラベル制約を満たす DNS 名のみを許容し、それ以外を通信前に設定エラーとする
  - 判定を通過した URL から要求先 endpoint を組み立て、IPv6 の場合は角括弧で authority を構成する。パスは常に所定の値のみとし、パス prefix を持つ配置を非対応とする
  - キャッシュ用の正規化接続先識別子を、scheme・小文字化ホスト・実効ポートから組み立てる
  - ネストした量指定子を用いず、ラベル単位の判定で正規表現を単一量指定子構成に保つ
  - 完了状態: 決定表の各構成要素を網羅した単体テストが通り、構文不正なホストが接続失敗ではなく設定エラーになることを確認できる

  - _Boundary: connection_settings_

- [ ] 2.3 数値設定と keep_alive の検証を実装する

  - temperature の負値・非有限を拒否し、model 名の空文字・空白のみを拒否して暗黙の既定モデル名で代替しない
  - keep_alive を単位なし十進数または単一単位付き文字列に限定し、複合単位表記を非対応とする

  - 完了状態: timeout の下限・上限・非有限、temperature の負値・非有限、keep_alive の許容 6 単位と非許容形式を網羅した単体テストが通り、実効 timeout が常に有効範囲内であることを確認できる

  - _Boundary: connection_settings_

- [ ] 2.4 (P) 抽出特徴の逐語根拠照合を実装する

  - 変換後の特徴が変換後の元プロンプトの部分文字列であり、かつ一致位置の直前・直後がいずれも Unicode の英数字でないことを検証する。文字列の端は境界とみなす
  - 処理順を「前後空白の除去 → 空要素の破棄 → 根拠照合」とし、後続へ渡す値を空白除去後の元表記とする
  - 畳み込みで文字列長が変わり得るため、正規化空間の位置を元文字列へ写像しない
  - 正規表現を使わず、境界を満たす出現が見つかった時点で探索を打ち切る
  - 完了状態: 語境界の開始側・終了側の双方の反例、区切りとしての下線、前後空白付き特徴、空要素の件数計上を網羅した単体テストが通る

- [ ] 3. Infrastructure: 通信・応答処理・資源

- [ ] 3.1 (P) Ollama への HTTP transport を実装する
  - 差し替え可能な transport 契約と、標準ライブラリによる既定実装を提供する。新規の外部依存を追加しない
  - 要求は POST 1 件に限り、リダイレクトの自動追従を無効化する。3xx はステータスを保ったまま結果として返し、Location の宛先へ再送しない
  - 応答本文を読み込み時に 1 MiB で打ち切り、上限到達を結果に明示する。全量をメモリへ読んでから判定しない
  - 名前解決・接続・送信・受信を含む 1 試行分の処理全体をワーカーで実行し、呼び出し側は単調時計の期限までのみ完了を待つ。期限到達時は結果を破棄してタイムアウトを送出する
  - 標準ライブラリの接続処理は名前解決をソケット生成と待ち時間設定より前に行うため、待ち時間の設定だけでは名前解決を中断できない。呼び出し側が観測する待機時間を名前解決込みで上限内に収めることを、この構造で保証する
  - ワーカー内でも待ち時間には残り時間を渡し、チャンク読み込みの各反復で期限を確認して自発的に打ち切る。放棄したワーカーは完了時に自身が生成した接続を必ず close し、共有状態へ書き込まない
  - HTTP エラー応答を例外ではなく結果として返し、ステータスと本文を保つ
  - 完了状態: スタブ接続に対し、3xx で第 2 要求が発生しないこと、1 MiB 超の本文が打ち切られることを検証する単体テストが通る
  - 完了状態: 名前解決を意図的に遅延させたスタブに対し、呼び出しが実効 timeout 以内に必ず戻ることを検証する単体テストが通る
  - _Requirements: 4.3, 4.5, 6.6, 12.3, 12.4_
  - _Boundary: ollama_client_

  - 完了状態: 引数へ別内容の Schema から構築した validator を渡すと、その Schema に基づいて適合・不適合が判定されることを単体テストで確認できる

- [ ] 4. Application: 実行経路の調停

- [ ] 4.1 設定検証と資源記述子確定の前段を実装する
  - 実行順序を「設定検証の一括実行 → 資源記述子の確定 → 空プロンプト判定 → キャッシュ照会」に固定する
  - 元プロンプトが空であるか否かによらず、当該実行で使用されない設定項目の検証も省略しない
  - prompt リソース 3 種を設定検証段で読み込む。payload 構築時ではない
